# Check cadence (US-023)

Run affected native checks and the shortest changed consumer path before review.
`skill://ship-loop` owns independent review order, round state and judgment;
[SKILL.md](SKILL.md) owns changed-path proof. Link unchanged evidence after fixes.

When commissioned to repair CI, put fast affected checks before merge and the full
battery on trunk's schedule (twice daily by default). Fix a red trunk run forward.
Native-OS qualification may use a release cadence. Use existing owned compute or
an already-approved service; choosing a schedule does not authorize spending.

Before deleting/rescheduling a check, name the consumer failure it catches and
where that proof will run. Keep independent contracts at their owner boundary;
`skill://test-audit` owns test pruning. A replacement must be proved before the
old mechanism retires. Keep maintained fixtures, not generated run output, in Git.

Done when affected fast checks gate the judged SHA, retained checks have a named
trigger, and the changed real consumer path has proof. A skipped required check
is a gap, not a green result.
