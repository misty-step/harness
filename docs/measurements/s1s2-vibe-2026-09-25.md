# System 1 / System 2 pilot: OMP against Pi with System 1

Recorded 2026-09-25 for **US-030** and **US-029**.
[Design](../system1-system2-harness.md). Per-run aggregates:
[s1s2-vibe-2026-09-25.json](s1s2-vibe-2026-09-25.json). Tasks, hidden-test
paths, and grading commands:
[s1s2-vibe-2026-09-25-tasks.json](s1s2-vibe-2026-09-25-tasks.json).

**Scope.** The operator's vibe check before any full evaluation. Six merged
harness pull requests (two small, two medium, two large) ran once each in two
arms. The plain-Pi control arm was held out of the pilot, so **nothing here
attributes a difference to System 1 alone**: every gap mixes Pi against OMP
with System 1. The [control run](s1s2-control-2026-09-25.md) that followed
compares Pi with and without System 1.

## Setup

- **Arms.** *OMP*: OMP 18.3.1 with `omp-config` at `ed16998`, every generative
  role (advisor and subagents included) pinned to the model under test, and
  provider fallback off. *Pi + System 1*: raw Pi 0.87.1 with the `s1s2`
  extension and Jev `typesafe/jev-1.13`.
- **Model.** `openrouter/deepseek/deepseek-v4.1-flash` at reasoning effort
  `high`, with a 384,000-token output ceiling in both wire APIs. The operator
  approved OpenRouter for this pilot as an exception to subscription-only
  models. Each run's parity record shows the same model, reasoning effort,
  storage flag, and ceiling. The wire API is a harness choice: OMP uses
  Responses and Pi uses chat completions.
- **Route.** Both harnesses and Jev called OpenRouter through an exe.dev
  `http-proxy` integration that injects the key, so no key was on the VM. A
  spend guard read the key's usage between runs (limit $20).
- **Isolation.** Agents ran as a separate user that could not read the hidden
  tests, the manifest, the runner's home, or other runs. Each run started from a
  fresh base-only checkout with no remote. `ssh`, `gh`, `pass`, and similar
  tools were shimmed off. Network egress was open (defect 1 below).
- **Execution.** Runner `e8d3f17` on a 2 vCPU, 8 GB exe.dev VM. One run at a
  time, arm order shuffled per task (seed 26). The 12 runs took 27 minutes.
- **Judges.** Opus 5.5, Gemini 3.1 Pro, and Grok 4.7 at high thinking, through
  OMP with no tools. Each saw the statement, the accepted reference diff, and
  the two candidate diffs under shuffled labels. They scored task, correctness,
  scope, and quality from 1 to 5, and ranked the candidates. A Jev panel scored
  each candidate's success and picked the best. The first pass lost six Grok
  verdicts because Grok tried to open files. The prompt now says the judge has
  no tools, and all 18 verdicts were rerun with it (23 minutes).

**Hidden tests barely separated the arms.** h2 failed in both arms for two
unrelated reasons:

- *An unnamed interface.* The hidden references test installs shared guidance
  with `--guidance session-close`, a section the statement never names. Both
  agents put the guidance in the existing `host-resources` section, so the
  installer the test invokes fails. This is neither arm's regression nor an
  environment failure: the base commit passes the old test, and only the
  reference change added that section.
- *A brittle assertion.* Pi + System 1 also failed one session-close assertion
  that searches the output for the substring `"ok": false`. Its `check --json`
  printed valid compact JSON (`{"ok":false,…}`) with the same value. The
  statement quotes the fragment as a value, not as required spacing.

Every other hidden test passed in both arms, so judged quality carries nearly
all of the quality signal here.

## What System 1 did (all six tasks)

- **Calls.** 40 Jev calls, none failed: 8.7 s of latency in total (218 ms per
  call, about 1% of the arm's wall-clock) and $0.004.
- **Brief.** 5 of 6 tasks got a briefing. In h2, none of the 24 candidate files
  cleared the relevance threshold.
- **Triage.** 5 long outputs judged: 1 elided, 4 left unchanged.
- **Monitor.** 23 checks, 3 notes suggesting a narrower search.
- **Done gate.** One chosen check per task. All 6 passed, so System 2 was never
  sent back.

That is about seven Jev calls per task against about 30 System 2 turns.

## Sample size this implies

These are paired tasks for 80% power at two-sided 5%. They use the pilot's
per-task spread for OMP against Pi + System 1 (five tasks, one run each):

| Measure | Pilot spread | 25% difference | 10% difference |
|---|---|---|---|
| Cost (log ratio SD) | 0.58 | 32 tasks | 238 tasks |
| Wall-clock (log ratio SD) | 0.97 | 90 tasks | 667 tasks |
| Turns (log ratio SD) | 0.41 | 16 tasks | 117 tasks |
| Output tokens (log ratio SD) | 0.46 | 20 tasks | 149 tasks |

Judged quality (difference SD 0.29 points) needs 11 tasks to detect a quarter
point and 3 for half a point. System 1's own effect, Pi + System 1 against plain
Pi, has an unmeasured spread. It is likely smaller than the gaps above, and an
effect near 10% would need hundreds of tasks.

## What a full evaluation would teach that the pilot cannot

1. **Whether System 1 causes anything.** OMP's advisor alone made 159 of its
   340 model calls, while System 1 acted lightly. Only the plain-Pi arm
   separates System 1 from the base harness.
2. **Run-to-run noise.** With one run per task and arm, no per-task difference
   can be separated from chance.
3. **Generality.** The pilot covered one TypeScript and Markdown repository,
   five usable tasks, and one inexpensive model. The full plan draws from six
   repositories and three sizes.
4. **Wall-clock.** The pilot's 27% total saving is inside the noise. Resolving a
   25% change takes about 90 tasks.
5. **Objective quality.** Hidden tests tied at the task level because the
   failures came from details the statement did not require. A full evaluation
   needs tests that bind only to the statement.

## Defects found and fixed

1. **Upstream contamination (h43).** Agent egress was open. The fix came in two
   stages.
   - *Address lock (`1c3b1dd` to `8e32a1f`).* The agent user could reach only
     loopback, DNS, and the proxy's address, through an iptables chain replaced
     in one transaction at every start. The runner refused to run while the
     agent could reach the repository host or GitHub. On the VM, a foreign rule
     ahead of the lock that admitted raw.githubusercontent.com made the runner
     exit 2; an invalid replacement left the previous rules intact; and the
     agent's `git ls-remote` and `curl` to GitHub failed at once. This lock
     still admitted everything behind the proxy's address, the exe.dev gateway
     that also serves the VM's `llm`, `notify`, and `reflection` integrations,
     and all of loopback, including exe.dev's Shelley agent on 127.0.0.1:9999.
     The h57 check runs below ran under it.
   - *Model boundary (`a8be6a4`).* The agent may now connect only to a model
     boundary on loopback and to ephemeral loopback ports for its own test
     servers. The boundary admits only the model under test and Jev. The
     preflight also probes the gateway, a raw address, and every listening
     service, and checks that the boundary refuses a foreign model. The
     [control-run record](s1s2-control-2026-09-25.md) holds its verification.
2. **Unpinned upstream.** OpenRouter sent most of OMP's Responses requests to
   Together ($0.30 in and $1.20 out per million tokens). It spread Pi's chat
   completions across Together, StreamLake, and Wafer. `--upstream` now pins one
   upstream with fallbacks off in both wire APIs (`PARITY_UPSTREAM`), and the
   runner requires it (`f5e065d`). The billed costs above reflect unpinned
   routing; the list-price row removes the price part of that difference.
3. **No output ceiling in OMP.** Pi sent 384,000 tokens and OMP none. The
   first launch found this and was discarded; the ceiling is pinned in both
   wire APIs (`4b67d44`).
4. **Agents could read hidden tests.** Both discarded launches ran agents as
   the runner's user. Agents now run as a separate user (`e8d3f17`).
5. **Judge prompt.** It now states that the judge has no tools and retries
   invalid verdicts (`7ff727b`).
6. **Stale spend reads.** OpenRouter's key usage trails requests: at
   `f499068`, a $0.001 limit still let the second arm start. `5b981ea` waited
   for the key's usage to move after each run. The model boundary (`a8be6a4`)
   replaced key-usage reads with a per-call ledger that admits a call only if
   settled costs plus every unsettled worst case fit under the limit.

## US-030 criteria walk for the pilot

The criteria were tightened after the pilot. Their walk at the final runner
revision is in the [control-run record](s1s2-control-2026-09-25.md).

| Criterion | Evidence | Status in the pilot |
|---|---|---|
| 1. Same prompt, model, effort, verbosity, ceiling, and upstream, recorded | Parity records. The scored pilot matched on everything but the upstream (defect 2). | Upstream unpinned; pinned from `1c3b1dd` on |
| 2. Every OMP role on the model, fallback off | Every OMP run's sessions, the advisor's included, used only `deepseek/deepseek-v4.1-flash` | Verified |
| 3. Fresh base-only checkout, shimmed tools, network limited to the model | Defect 1 | Not met: egress open in the scored runs, gateway and loopback open under the address lock |
| 4. Hidden tests and usage report per run | Each run record has hidden and regression results, tokens by category, wall-clock, and turns | Verified |
| 5. Judges see only the task, the accepted change, and shuffled diffs | The judge prompt, with labels shuffled per task | Verified |
| 6. Strict spend cap | Key-usage guard only (defect 6) | Not met in the pilot |

## Reproduce

1. Create a VM (2 vCPU, 8 GB) whose runner user has passwordless sudo. Put
   Bun 1.4.2, `omp` 18.3.1, and `pi` 0.87.1 in `/usr/local/bin`. Add an agent
   user, set both homes to mode 750, and add the runner user to the agent's
   group. Install `omp-config` into the agent's home, and copy the candidate
   revision root-owned to `/opt/s1s2-src`.
2. Create the proxy with `ssh exe.dev integrations add http-proxy --name
   openrouter-eval --target https://openrouter.ai --bearer=- --attach
   vm:<vm>`, passing the key on stdin. The runner points Pi at its model
   boundary; for the OMP arm, set `providers.openrouter.baseUrl` to
   `http://127.0.0.1:18181/api/v1` in the agent's `~/.omp/agent/models.yml`.
3. Write each task's hidden tests to `<hidden>/<task>/<path>` from `git show
   <merge>:<path>`. Apply the manifest's `relaxed` edits.
4. Run from the candidate revision as the runner user:

   ```sh
   bun pi-config/extensions/s1s2/eval/vibe.ts --manifest tasks.json \
     --hidden <hidden> --out <out> --agent-user <agent> --code-root /opt/s1s2-src \
     --arms omp,s1s2 --model openrouter/deepseek/deepseek-v4.1-flash --thinking high \
     --max-output 384000 --upstream deepseek \
     --openrouter-base https://openrouter-eval.int.exe.xyz --spend-limit 20 --seed 26
   ```

5. Copy `<out>` to the workstation and judge:

   ```sh
   pass-env run -f .env.pass -- bun pi-config/extensions/s1s2/eval/judge.ts \
     --manifest tasks.json --out <out> --arms omp,s1s2 \
     --price-model deepseek/deepseek-v4.1-flash --seed 26
   ```

The scored pilot predates the required upstream pin, the model boundary, and
the spend ledger, so this command reproduces its tasks and arms, not its
routing, open egress, or spend guard.
