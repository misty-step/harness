# System 1 / System 2 prototype: real-task smoke on exe.dev

Recorded 2026-09-25 for **US-029**. [Design](../system1-system2-harness.md).

**Scope.** Two runs of one real task, both in the System 1 / System 2 arm.
This record proves that the prototype runs a real repository task end to end
on exe.dev and records everything the evaluation needs to measure. It is **not
a comparison**: no OMP or raw-Pi run was made, and n = 2 supports no claim
about cost, speed, or quality.

On the base tree, the same CLI probe prints `+0 / -0 in 0 file(s)`, which
reproduces the defect. The OpenRouter key's usage rose by $0.5306 across both
runs and the day's small probes. The Pi-recorded costs account for $0.5234 of

**The single hidden-test failure has the same cause in both runs.** The
reference test requires byte equality with `git log -p`, including commit
headers. Both runs chose header-free `git log --patch --format=` output so that
the file splitter sees only `diff --git` sections, and both tested that choice.
The statement did not specify an output format, so this assertion binds to the
reference implementation rather than to the task. The evaluation plan's
curator screen now calls out this class.

## What System 1 did

- **Brief (both runs).**
  - 30 candidates from 12 prompt terms, found in 55 ms of Git search and scored
    in one Jev batch of 262–295 ms.
  - Both runs named the same four files: `engine.ts`,
    `omp-diff-review.ts`, `omp-diff-review.test.ts`, and the diff-review
    `engine.ts` shim.
  - Their scores were 0.97 / 0.96 / 0.86 / 0.51 in run 1 and 0.96 / 0.95 /
    0.87 / 0.70 in run 2. The state was identical, so Jev varies by up to about
    0.2 near the middle of the scale.
  - Scope was scored at about 2 (one area), which allows up to six files.
  - In both runs, System 2's first two turns read the top two files. In run 2,
    the first read went to `engine.ts` lines 1140–1240, around the briefed
    `L1163: export function getGitDiff`.
- **Triage.** Never triggered: no bash output exceeded the 8 KB / 120-line bound.
- **Monitor.** One periodic check at turn 8, with no note in either run.
- **Done-gate.**
  - *Run 1.* System 2's last check was `./scripts/verify shared 2>&1 | tail -15;
    …`. The v0 word-based classifier counted it as verification, and System 1
    stood down.
  - *Run 2.* The fixed classifier rejects a piped status. Jev chose
    `bun test ./omp-config/bin/omp-diff-review.test.ts` (p 0.93). System 1 ran
    it in 212 ms, got exit 0, and settled without an extra System 2 turn.

## Defects the smoke found and fixed

1. **Unfinished nudge on short answers (`f42c16a`).** A cheap-model probe on
   the VM nudged a correct one-word answer as unfinished (p 0.81). The fix
   rewrote the criteria and raised the threshold to 0.8. A live re-probe scored
   the same case at 0.63 and a stopped-midway message at 1.0.
2. **Edits made through bash were invisible (`d70f52f`).** Run 1 patched files
   only through `python3` heredocs, so the ledger reported eight turns without
   an edit. Edits are now read from the working-tree fingerprint. A regression
   test fails when detection is based on tool names.
3. **False verification (`d70f52f`).** A command that merely contained `test`,
   or piped a check into `tail`, counted as verification. Now only a known
   runner or discovered check whose exit status is the verdict counts. A
   regression test fails on the old classifier.

## Open items for the pilot

- Brief sample lines are the first grep matches, such as file-header comments,
  not the lines matching the rarest terms.
- The triage path and monitor notes have only fixture evidence
  (`s1s2.test.ts`), not real-task evidence.
- The scoped check runs from the repository root. A test that depends on its
  working directory would fail spuriously. The pilot should look for this.
