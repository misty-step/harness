# References

Favourite sources we learned from. None of these upstream packs or tools is installed by mistystack; links are reading material, not dependencies. Adapted material and its licences are recorded in [ATTRIBUTION.md](../ATTRIBUTION.md).

- [pstack — Lauren Tan](https://github.com/cursor/plugins/tree/main/pstack): one mode, small principles, playbooks, setup and a human guide.
- [Matt Pocock's skills](https://github.com/mattpocock/skills): shaping, domain language and instructions agents can follow.
- [Emil Kowalski's skills](https://github.com/emilkowalski/skills): design engineering and purposeful motion.
- [Impeccable — Paul Bakaus](https://github.com/pbakaus/impeccable): interface critique, accessibility and polish.
- [Taste — Leon Lin](https://github.com/Leonxlnx/taste-skill): deliberate visual choices rather than generic output.
- [Hallmark — Nutlope](https://github.com/Nutlope/hallmark): coherent design direction for coding agents.
- [Kody — Kent C. Dodds](https://github.com/kentcdodds/kody): an agent workflow to study; FSL-1.1 reference only, no copied material.
- [TypeSafe](https://docs.typesafe.ai/): typed judgments as composable program primitives.
- [Felix Rieseberg, “How to be more ambitious”](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/): deepen the method rather than inflate the scope.
- [Nico Bailon, skill-diet](https://github.com/nicobailon/skill-diet): compare instructions with both their earlier form and no skill.
- [Martin Gratzer on slices](https://x.com/mgratzer/status/2114726996869595265): useful vertical slices with independent review and a risk check.
- [Kent C. Dodds, “Write tests. Not too many. Mostly integration.”](https://kentcdodds.com/blog/write-tests): confidence through behavior across real boundaries.
- [John Ousterhout, A Philosophy of Software Design](https://web.stanford.edu/~ouster/cgi-bin/book.php): deep modules and small interfaces.
- [Linus Torvalds, Linux kernel coding style](https://github.com/torvalds/linux/blob/master/Documentation/process/coding-style.rst): simple code, clear ownership and maintainable interfaces.
- [Jakub Krehel, “Less is more, more or less”](https://jakub.kr/writing/less-is-more): subtraction follows understanding.
